# 文体・スタイルガイド

過去の投稿25件以上を分析し、共通する書き方の癖・パターンをまとめたもの。

## 文体

### 基本ルール

- **常体**を基本とする（「〜する」「〜できる」「〜だった」）
- 丁寧語は冒頭の挨拶的な文や読者への配慮で使う程度（「〜幸いです」「〜ください」）
- 「〜した。」「〜だった。」のような過去形の語り口が多い
- 口語的なカジュアルさを持つ（「〜してみる」「〜だが」「〜かも？」「〜なのでは？」）

### 冒頭の書き出しパターン

以下のいずれかで始めることが多い:

- 「備忘録として記事にしました。」
- 「〜で、〜がありました。〜備忘録としてまとめます。」
- 「〜がしたかった。」「〜が気になりました。」
- 「〜なので実際に試してみる。」
- 「作業の備忘録になります。」「あくまでご参考になれば幸いです。」（WooCommerce系）

### 語尾の傾向

- 手順の説明: 「〜する。」「〜を作成する。」「〜を編集する。」
- 結果の報告: 「〜できた。」「〜になった。」「〜が表示される。」
- 補足: 「〜とのこと。」「〜のよう。」「〜らしい。」
- 注意喚起: 「〜すること」「〜に注意」

## 見出し構成

### レベル使い分け

- `##` : メインセクション（はじめに、手順、まとめ、参考 等）
- `###` : 手順番号（`### 1. 〜`、`### 2. 〜`）またはサブセクション
- `####` : 手順内のさらなる細分化（`#### (1) 〜`）
- `#` : タイトルと同じ見出しを本文冒頭に置くことが稀にある（基本は不要）

### よく使うセクション名

| セクション | 用途 |
|---|---|
| はじめに / 動機 | 記事の背景・きっかけ |
| やりたいこと / 目的 / 課題 | 解決したいことの説明 |
| やったこと | 実施内容の概要 |
| 本記事で分かること | 箇条書きで記事の成果を列挙 |
| 手順 | 番号付き手順 |
| 方法 / 解決策 | コード例と説明 |
| 起きた問題 | エラーや不具合の説明 |
| 原因 | 問題の原因分析 |
| まとめ | 箇条書きで要点整理 |
| 補足 | 追加情報・付随する知識 |
| 注意事項 | 注意すべきポイント |
| 参考 | 参考URL一覧 |
| ハマったところ | 躓いたポイントの共有 |

## フォーマット・装飾

### 水平線（---）

- セクション間の区切りに積極的に使用する
- 特に「冒頭説明」→「本題」の間、「本題」→「まとめ/参考」の間

### 強調

- `**太字**` : 重要なキーワード、設定値、ファイル名の強調
- `` `バッククォート` `` : コマンド、関数名、ファイルパス、設定値
- 太字を強調に使い過ぎない。ポイントとなる箇所のみ

### コードブロック

- 言語指定を必ず付ける（php, bash, yaml, json, javascript, sql 等）
- コード内にコメントで説明を入れることがある（`// ←ここ`、`// 追加`、`# 追加`）
- 短いコマンドは ``` のみ（言語指定なし）のこともある

### 箇条書き

- `-` を使用（`*` ではなく）
- ネストする場合はインデント4スペースで `-` を続ける
- 手順の補足や列挙に多用する

### 表

- 比較表やフック情報の整理に使用する
- Markdown のパイプテーブル形式

### 画像

- スクリーンショットは `![image.png](URL)` 形式
- Qiita の画像ストレージ URL を使用

## タイトルの付け方

### パターン

- `【カテゴリ】具体的な内容` が最も多い
  - 例: `【EC-CUBE4.3】プラグインを開発してみる その５`
  - 例: `【PHP】array_mergeで数値キーが振り直される問題と + 演算子による解決法`
  - 例: `【WooCommerce】注文詳細ページの「再注文」ボタンを非表示にする方法`
  - 例: `【Chrome】HTTP環境で位置情報などのセキュアな機能を一時的に使えるようにする方法`
- カテゴリなしのシンプルなタイトルも稀にある
  - 例: `Chatwork MCPサーバーを試す`

### カテゴリの選び方

- フレームワーク・ツール名: EC-CUBE4.3、CakePHP、WooCommerce、Docker
- 言語名: PHP
- ツール名: Chrome

## タグの付け方

- 2〜5個
- 主要技術（言語・フレームワーク）を先頭に
- よく使われるタグ: PHP, Symfony, doctrine, twig, EC-CUBE4, WordPress, WooCommerce, CakePHP, Docker, MCP

## WooCommerce 系記事の特徴

WooCommerce 系の記事には独自のパターンがある:

- 冒頭に「やりたいこと」→ 1行説明 → 箇条書きで「作業の備忘録になります。」「あくまでご参考になれば幸いです。」
- 「方法」セクションで `functions.php` のコードを提示
- 「フック情報」セクションで表形式でフック名・関数名・優先度等を整理
- 「参考」セクションに WooCommerce の Hook Reference リンク

## AI利用の明記

- 過去の記事では AI 利用を末尾に明記していた例がある:
  - 「※ この投稿は、ChatGPTにひな型を作ってもらってます。」
  - 「※この記事はAIに書いていただいています。」
  - 「※ こちらの記事はChatGPTにまとめてもらいました。」
- 現在は Claude Code を使用しているため、必要に応じて末尾に明記する
- ユーザーが明記不要と言えば省略する
