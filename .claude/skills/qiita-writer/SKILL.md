# Qiita Writer

Qiitaリポジトリ（public/ 配下）に記事を作成する際、過去の投稿スタイル・構成・文体を統一するためのスキル。

## ワークフロー

1. ユーザーから原文・テーマ・メモを受け取る
2. references/writing-style.md を読み、文体・構成ルールを確認する
3. 記事の種類を判定し、適切な構成パターンを選ぶ
4. `public/<slug>.md` として記事を作成する

## 記事ファイルの形式

### フロントマター（必須）

```yaml
---
title: 【カテゴリ】記事タイトル
tags:
  - タグ1
  - タグ2
private: false
updated_at: ''
id: null
organization_url_name: null
slide: false
ignorePublish: false
---
```

- `title`: 【】でカテゴリを囲む形式を基本とする（例: 【EC-CUBE4.3】、【PHP】、【Chrome】）
- `tags`: 2〜5個。主要技術を先頭に
- `updated_at` と `id` は空・null のまま（Qiita CLI が自動付与）

### ファイル名

- 英語のケバブケースのスラッグ（例: `chrome-flags-insecure-origin-geolocation.md`）
- 内容が分かる名前にする

## 文体・構成ルール

詳細は [references/writing-style.md](references/writing-style.md) を参照。

### 要点

- **冒頭**: 1〜2行で動機・背景を簡潔に書く（「備忘録として」「〜がありました」など自然な書き出し）
- **見出し**: `##` を主に使用。`###` は手順番号付きで使う（例: `### 1. 〜`）
- **セクション区切り**: `---`（水平線）でセクションを区切る
- **コードブロック**: 言語指定を必ず付ける（```php, ```bash, ```yaml 等）
- **敬体**: 「〜です」「〜ます」は控えめに。「〜する」「〜できる」の常体を基本とする
- **補足・注意**: 記事末尾に「## 補足」「## 注意事項」としてまとめる
- **参考リンク**: 記事末尾に「## 参考」セクションを置く（あれば）

## 記事の構成パターン

### パターン A: 備忘録・Tips系（短め）

```
冒頭（1〜2行の動機）
---
## 背景 / やりたいこと
## 解決策 / 方法
## 手順（必要なら）
---
## 注意事項（必要なら）
## 補足（必要なら）
```

### パターン B: 問題解決系

```
冒頭（1〜2行の背景）
---
## 起きた問題 / 課題
## 原因
## 解決策 / 解決方法
---
## まとめ
## 参考
```

### パターン C: 手順・チュートリアル系

```
## はじめに / 動機
## 本記事で分かること（箇条書き）
## 手順
### 1. 〜
### 2. 〜
### 3. 〜
---
## まとめ（必要なら）
## 参考
```

### パターン D: 紹介・解説系

```
## はじめに
## 概要
## 主な仕様 / 構成（表形式）
## 実装 / コード例
---
## まとめ
## 参考
```
